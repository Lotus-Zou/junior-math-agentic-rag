# 初中数学错题系统准确性与自适应练习设计

日期：2026-08-26

## 1. 背景

当前系统已经具备本地确定性求解、RAG、Critic、会话状态和 bad case 记录，但仍存在两个用户可见问题：

1. 部分短指令未被路由，例如用户在系统提示后输入“几何”，请求仍进入复杂推理链路并在 8 秒后显示内部超时信息。
2. 练习由小型固定题目集合轮换，无法根据年级、知识点、历史表现和难度偏好生成足够多样的题目。

逐个增加关键词只能缓解单个案例，不能建立成熟产品所需的响应可靠性。本设计将系统改为准确性优先的分层编排，并引入经过确定性验证的自适应练习生成。

## 2. 目标

- 初中数学范围内的完整题目必须返回经过验证的答案或解题引导。
- 题目条件不足时返回具体、可操作的追问，不猜测答案。
- 短指令、会话控制和难度调整不调用外部模型即可完成。
- 用户界面不显示模型超时、检索异常、Critic 失败等内部实现信息。
- 自适应练习根据用户需求和历史表现调整知识点与难度，并避免短期重复。
- 每次故障、降级和校验失败仍完整记录到后台 Trace 与 bad case。

## 3. 非目标与准确性边界

- 不承诺对信息缺失、图片不可读或超出初中数学范围的问题生成确定答案。
- 不把“始终输出一个答案”作为成功，因为这会鼓励无依据回答。
- 对无法验证的问题，准确的澄清问题或范围说明属于有效结果。
- 不依赖增加无限重试来提高成功率；每条推理路径必须有明确预算和终止条件。

## 4. 用户响应契约

API 的每次成功响应必须属于以下四类之一：

| 类型 | 使用场景 | 用户可见结果 | 准确性要求 |
| --- | --- | --- | --- |
| `verified_answer` | 完整、可求解的问题或答案核对 | 解题引导、推导和结论 | 确定性验算或独立 Critic 通过 |
| `guided_exercise` | 知识点选择、换题、难度调整 | 一道条件完整且答案暂时隐藏的练习 | 题目与标准答案预生成并校验通过 |
| `clarification_required` | 条件、目标或图形信息不足 | 明确指出缺失项并提出单一追问 | 不包含猜测性结论 |
| `supported_refusal` | 超出课程范围或违反安全策略 | 说明边界并提供可处理的替代方向 | 不泄露内部配置和系统提示词 |

`timeout`、`model_error`、`retrieval_empty` 和 `critic_rejected` 只能作为内部 Trace 状态，不能成为用户响应类型。

## 5. 分层运行架构

请求按以下顺序处理：

```text
输入规范化
  -> 会话控制与短指令分类
  -> 当前题目状态判定
  -> 题目完整性分析
  -> 本地确定性求解
  -> 多路 RAG 检索与生成
  -> 独立 Critic 校验
  -> 有界重新检索或备用推理
  -> 精确追问或已验证结果
```

### 5.1 输入规范化

- 执行 Unicode NFKC 规范化、空白折叠和标点归一化。
- 保留数学符号、LaTeX 和几何记号。
- 拦截控制字符、提示词提取和角色伪造。

### 5.2 本地意图分类

本地分类器必须覆盖：

- 会话控制：换个问题、重新开始、清空当前题。
- 主题选择：代数、几何、一次函数、概率统计等。
- 练习控制：再来一道、换一道、难一点、简单一点、给提示、看答案。
- 学习动作：求解、错因分析、答案核对、知识点解释。

分类器使用严格词典、结构规则和当前会话状态组合判断。只有无法可靠分类的完整自然语言题目才进入模型意图识别。

### 5.3 题目完整性检查

解析结果至少包含：题干、已知条件、求解目标、年级、知识点、图形依赖和学生作答。

完整性检查器输出：

- `complete`：具备可求解条件。
- `missing_conditions`：列出缺失条件，并只追问最关键的一项。
- `requires_image`：明确要求上传或描述无法从文本恢复的图形信息。
- `out_of_scope`：进入范围说明。

### 5.4 确定性求解

代数、方程、不等式、函数、统计、概率和可结构化的基础几何题优先进入本地求解器。求解后至少执行一项独立校验：

- 方程与不等式：代回原式或区间验证。
- 函数：代入给定点、斜率和截距复核。
- 几何计算：角和、长度关系或定理前提复核。
- 概率统计：样本空间、计数或汇总结果复核。

### 5.5 RAG 与生成

确定性求解器无法覆盖时，执行 BM25、稠密向量和轻量知识图谱检索，经 RRF 融合与重排形成带来源上下文。生成 Agent 只能使用题设和检索证据，不得补造条件。

### 5.6 独立 Critic

Critic 与生成 Agent 隔离，检查：

- 是否使用了题目中不存在的条件。
- 每个关键公式或定理是否适用。
- 推导是否存在跳步、符号错误或逻辑循环。
- 最终结论是否回答了用户目标。
- 引用是否真实支撑对应陈述。

Critic 失败时允许一次重新检索和一次备用推理。仍无法通过时返回精确追问，不输出草稿答案。

## 6. 自适应练习生成

### 6.1 练习请求模型

练习请求包含：

- `grade`：七、八、九年级或未知。
- `topic`：章节和细分知识点。
- `difficulty`：1 至 5。
- `exercise_type`：计算、选择、证明、应用或综合。
- `recent_template_ids`：最近使用的模板。
- `recent_answer_signatures`：最近标准答案特征。
- `mastery`：用户对相关知识点的掌握度。

只输入“几何”时，系统使用用户画像中的年级和掌握度；没有历史时从难度 2 的基础几何题开始。

### 6.2 参数化生成

题目由可验证模板和受约束参数生成。模板定义：

- 适用年级、知识点、题型和难度范围。
- 参数取值域和互斥条件。
- 题干渲染器。
- 标准答案求解器。
- 条件充分性与答案唯一性校验器。
- 提示阶梯和常见错因。

生成过程先产生题目与隐藏答案，再执行求解和校验。未通过校验的候选题不会展示给用户。

### 6.3 难度调整

- 上一题正确且步骤完整：默认提高 1 级，最高为 5。
- 上一题错误但能在提示后修正：保持难度，切换参数或相邻题型。
- 连续错误或明确要求“简单一点”：降低 1 级并拆分知识点。
- 明确要求“难一点”：提高 1 级，但不得越过年级课程边界。
- 用户明确指定难度时覆盖自动调整。

### 6.4 去重

候选题在展示前检查：

- 最近 20 道题不得重复 `template_id + normalized_parameters`。
- 最近 10 道题不得具有相同题干指纹。
- 连续 5 道题不得重复相同答案特征和设问结构。

去重失败时重新采样参数或切换同知识点模板，不进入外部模型重写。

## 7. 会话与状态

会话状态分为：

- 当前题目状态：题干、隐藏标准答案、提示级别、用户作答和校验结果。
- 练习偏好：年级、主题、难度、题型和最近题目指纹。
- 掌握度摘要：知识点正确率、提示依赖和常见错因。

“换个问题”清除当前题目状态，但保留练习偏好与掌握度。“重新开始”同时清除当前题目和会话偏好。新的完整题目不得继承上一题的标准答案或 Critic 期望值。

## 8. 超时与故障处理

- 本地分类、出题和确定性求解不受外部模型超时影响。
- 外部推理采用可配置总预算，默认 30 秒；准确性门禁不因接近预算而跳过。
- 达到预算时，只能返回已经验证的局部结论或 `clarification_required`。
- 前端展示教学语言，例如“目前缺少图中点 D 的位置关系，请补充”，不展示服务名、重试次数和超时秒数。
- 后台 Trace 记录超时节点、耗时、检索结果、Critic 报告和最终降级类型。

## 9. API 与前端变更

响应新增或统一以下字段：

```json
{
  "response_type": "verified_answer",
  "answer": "...",
  "validation_passed": true,
  "intent": "solve",
  "conversation_history": [],
  "conversation_summary": "",
  "exercise_state": null,
  "clarification": null,
  "sources": [],
  "metrics": {}
}
```

前端根据 `response_type` 渲染答案、练习或追问。任何网络和服务异常使用中性提示并允许保留输入重试，但服务正常返回时不得把内部异常文本作为答案。

## 10. 测试与发布门禁

### 10.1 单元与契约测试

- 短指令：几何、代数、一次函数、换题、再来一道、难一点、简单一点。
- 题目状态：新题隔离、继续追问、查看提示和答案核对。
- 出题质量：条件充分、答案唯一、难度有效、答案隐藏和短期去重。
- 确定性求解：答案反向验算和边界条件。
- API：四种响应类型的 Schema 与前端状态同步。

### 10.2 集成与故障注入

- 模型超时、模型异常、检索为空、Critic 拒绝和缓存异常。
- 故障时仍返回精确追问或已验证局部结果。
- 页面不得出现内部超时、堆栈、供应商或密钥信息。

### 10.3 评测数据

- 保留现有 1000 条数学基准。
- 新增短指令和多轮练习状态集。
- 新增参数化题目属性测试，覆盖不同随机种子和难度。
- 每个线上 bad case 在修复前先成为失败测试，修复后加入永久回归。

发布门禁要求：基础数学基准、短指令、多轮状态、题目质量和故障注入全部通过。准确性校验失败的版本不得发布。

## 11. 可观测性

Trace 至少记录：

- 规范化输入和意图分类结果。
- 当前题目状态是否继承或重置。
- 求解器、检索器和工具调用。
- 每轮校验结果与失败原因。
- 练习模板、难度、参数指纹和去重次数。
- 最终响应类型、总耗时和降级原因。

用户看到的响应与后台诊断严格分离。

## 12. 迁移顺序

1. 建立统一响应类型与用户可见错误策略。
2. 补齐短指令、主题选择和状态隔离。
3. 实现自适应练习请求、参数化模板、确定性验证和去重。
4. 接入掌握度与难度调整。
5. 重构 RAG、Critic 和超时降级为统一可靠性编排。
6. 扩展评测脚手架、故障注入和前端端到端测试。

每一阶段先添加失败测试，再实施最小变更，并在阶段结束时运行全量门禁。

## 13. 验收标准

- 输入“几何”会生成一道人机可验证、答案隐藏的几何练习。
- 连续请求练习不会短期重复，并能响应难度升降要求。
- 完整可求解题目只在校验通过后输出结论。
- 信息不足时指出具体缺失项，不猜测答案。
- 模型和检索故障不会向用户展示内部超时文案。
- 任一新 bad case 都有可复现 Trace 和永久回归测试。
